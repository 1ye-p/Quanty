# cquant.ml_lab

ML training, validation, and experiment tracking for quantitative strategies.

## Overview

`ml_lab` integrates feature loading, rolling model training, and prediction
persistence into a single cohesive pipeline.  It is built on Polars DataFrames
and supports LightGBM and XGBoost trainers out of the box.

---

## Quick Start

```python
from cquant.datahub.catalog import Catalog
from cquant.ml_lab.pipeline import run_ml_prediction_pipeline

catalog = Catalog.from_env()

# features must contain [asset_id, trade_date, <feature_cols...>, ret_5d]
model_id = run_ml_prediction_pipeline(
    catalog=catalog,
    features=features_df,
    target_col="ret_5d",
    model_id_prefix="momentum",
    n_splits=3,
    gap_days=5,
    horizon="5d",
)
# model_id can be passed to MLModelStrategy
```

`run_ml_prediction_pipeline` trains LightGBM over walk-forward splits and
writes predictions to `gold_predictions` via the Catalog, then returns the
`model_id` string.

## Key Modules

| Module | Purpose |
|---|---|
| `pipeline.py` | One-shot helper: feature loading → rolling train → persist predictions |
| `base.py` | `ModelArtifact` dataclass + `Trainer` ABC |
| `preprocessing.py` | Cross-sectional z-score, winsorize, null-fill (Polars) |
| `labels.py` | Forward-return label generation; clips raw returns to **[-0.5, 0.5]** |
| `datasets.py` | `MLDataset` wrapper used by validators |
| `experiments.py` | `ExperimentTracker` — log runs, metrics, artifacts |
| `trainers/lgbm.py` | `LGBMTrainer` — LightGBM regression trainer |
| `trainers/xgb.py` | `XGBTrainer` — XGBoost regression trainer |
| `walk_forward.py` | `WalkForwardValidator` — rolling train/valid splits |
| `purged_kfold.py` | `PurgedKFold` — purge + embargo K-fold for time-series |

---

## PurgedKFold vs WalkForwardValidator

| | `PurgedKFold` | `WalkForwardValidator` |
|---|---|---|
| Split style | K non-overlapping validation folds distributed across the full dataset | Rolling expanding train window, sequential validation folds |
| Leakage prevention | Purge window (removes train samples whose target overlaps validation) + embargo after validation end | Gap days between train end and validation start |
| Use case | Research / hyperparameter search across the full history | Production-style backtesting and pipeline training |

## Data Flow

```
Raw features DataFrame
  [asset_id, trade_date, factor_1 … factor_N, ret_5d]
        |
        v
  preprocessing.py
  cross_sectional_zscore / winsorize / fill_nulls
        |
        v
  labels.py  (clip returns to [-0.5, 0.5])
        |
        v
  WalkForwardValidator.split()
  ┌──────────────┬──────────────┐
  │  train_df    │  valid_df    │  × n_splits
  └──────────────┴──────────────┘
        |
        v
  LGBMTrainer.fit()  →  ModelArtifact
        |
        v
  trainer.predict_and_persist()
        |
        v
  Catalog  →  gold_predictions table
```

---

## Return Clipping

Labels generated by `labels.py` are clipped to **[-0.5, 0.5]** to prevent
extreme return outliers from distorting model training.  This is applied before
any split or fitting step.
